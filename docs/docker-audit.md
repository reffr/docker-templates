# Docker audit — 2026-11-03

Scope: every file in the repo at `main` (`9f0321b`). The repo contains **3 Dockerfiles, 2 supervisord configs, 2 Openbox menus and 1 build script**. There are **no `docker-compose`/`compose.yaml` files and no Unraid XML templates** here (the templates live in `kilrah/unraid-docker-templates`, which was out of scope). Runtime concerns such as restart policy, resource limits and host port bindings are therefore set by those templates, not by anything in this repo. They are listed below as items to check there.

| 9 | **Medium** | `arduinoide2/Dockerfile:39` | The entrypoint runs `chmod 0666 /dev/tty*`. | This makes every tty device visible in the container world-writable, including the console and pty devices if `--privileged` or `/dev` is bind-mounted. ### Checked and found clean

- **Secrets/tokens**: I scanned every tracked file and the full git history for passwords, tokens, API keys, private keys and cloud credential patterns. There were **no matches**; the only hits were the package name `libsecret-1-0` and the flag `--no-url-password`.
- **`:latest` tags in `FROM`**: none. Every base uses an explicit tag (`golang:1.14-buster`, `ubuntu:22.04`, `debian:buster`, `nextcloud:$VERSION`). All tags referenced in the repo exist on Docker Hub (I checked `debian:buster`, `ubuntu:22.04`, `golang:1.14-buster`, `nextcloud:27.1.10`, `28.0.6`, `29.0.2`, `29.0.2-fpm`, `29`). No `FROM` is pinned by digest; you could add digests for reproducibility, but that would turn off base-image updates, so I left that decision to you.
- **Internal ports**: VNC 5900 is bound to `-localhost` in both images, so it's correct. Only 8080 is exposed (see #3).
- **Deprecated compose syntax / duplicate service definitions**: there are no compose files, so this doesn't apply.

## What I could not verify

- **Builds**: this environment has the Docker CLI and Compose v5.6.1 but **no Docker daemon**, so none of the images were built, and `docker build --check` could not run. There are no compose files, so `docker compose config` doesn't apply. I reviewed the Dockerfile edits by hand. I tested the healthcheck command on its own: it exits 0 against a listening port and 1 against a closed one.
- **Linting**: I tried to run hadolint, but this session's permission policy blocked running the downloaded binary.
- **GitHub sources**: `github.com/.../archive/*.tar.gz` returned 403 through this environment's proxy. Because of that, I couldn't confirm the dlib/pdlib archive hashes or pick a pdlib tag to pin.
- **FreeFileSync download**: the URL answers `200 text/html`. I couldn't tell whether it serves the tarball to non-browser clients or only a gate page.
- **PHP ABI of each `nextcloud` tag** (#6/#7): this is based on upstream's published PHP versions, not on looking inside the images.
- **Unraid templates**: these live in a different repository. I couldn't check their restart policies, port bindings or resource limits here.
